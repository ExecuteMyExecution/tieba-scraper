# 贴吧内容采集台

一个基于 [aiotieba](https://github.com/lumina37/aiotieba) 的本地百度贴吧内容抓取与筛选工具。后端使用 FastAPI + SQLite，前端为无需构建的原生 Web 页面。

## 功能

- 按吧名抓取指定页数的主题帖
- 按主题帖发布时间范围过滤
- 可按首楼图片条件抓取：不限、有图片、无图片、人像图片
- 抓取页数最高 100 页
- 后台抓取、实时进度与错误提示
- 按关键词、吧名、作者、日期、有无图片筛选
- 可折叠采集侧栏，内容筛选保持顶部横向布局
- 默认多列卡片展示，也可切换为列表视图
- 图片使用站内遮罩大图预览，支持左右切换和键盘操作
- 每个贴吧只保留该吧最新一次抓取结果，不同贴吧的结果会同时保存在资料库中
- 内容筛选区可选择查看全部贴吧或某一个贴吧
- 筛选条件、采集侧栏状态、展示方式、卡片大小和每页数量会保存在当前浏览器中，刷新后自动恢复
- 人像采集先保存本次完整快照，再基于同一快照识别并发布结果
- 24 小时内重复出现的主题会复用首楼详情；人像识别结果按图片 URL、检测器版本缓存 14 天
- 同一次任务跨页重复出现的主题只处理一次；设置开始日期后，到达全是更早主题的页面会自动结束后续扫描
- 首楼详情请求采用动态全局限速；遇到 429 会立即降速，连续稳定后逐步恢复，429/5xx 会指数退避并自动重试
- 已删除主题单独计为“跳过”且不再补抓；真正未完成的主题才会让任务标记为“部分完成”
- 同一时间只允许一个采集任务，避免多个页面同时抓取造成限流和结果相互覆盖
- 刷新页面后会自动恢复正在运行的任务进度，也可主动取消；取消不会覆盖该吧上一次发布的数据
- 进度区显示首楼/图片缓存、自动重试、跳过、主题失败与图片识别失败数量
- 按发布时间、回复数、浏览数排序，支持分页

## 启动

建议使用 Python 3.10 或更高版本。

使用 Git Bash 或 WSL 时，在项目目录运行：

```bash
bash start.sh
```

首次运行时，脚本会自动创建虚拟环境并安装依赖；之后如果依赖缺失，也会自动补装。启动后打开 <http://127.0.0.1:8000>。

在 WSL / Ubuntu 中首次运行前，请确认已安装 venv 组件：

```bash
sudo apt install -y python3-venv
```

否则 `python3 -m venv` 可能留下一个没有 pip 的空 `.venv`，启动时会报 `No module named uvicorn`。

## 说明

- “抓取页数”指贴吧主题列表页数，每页最多约 30 条，上限为 100 页。
- “首楼图片条件”会检查主题首楼，只有符合“不限 / 有图片 / 无图片 / 人像”条件的主题才会写入资料库。“人像”在本机组合检测真人面部、完整/局部身体、遮脸和背影：先做人脸判断，再按需运行人体目标、姿态与人体分割模型；图片不会发送给外部识别服务。
- 人像任务会先把这一任务扫描到的原始帖子写入独立快照，再识别其中的图片，最后一次性替换页面内容；识别过程不会再次抓取贴吧列表。
- 图片下载或解码暂时失败时会重试并计入“图片失败”，不会误判为非人像，也不会把失败结果写入识别缓存；下次任务仍会重新识别。
- 日期按本机时区解释，结束日期包含当天。
- 数据保存在 `data/tieba.db`；新任务成功后只会原子式替换同一贴吧的旧结果，其他贴吧不受影响；抓取失败时保留该吧上次数据。
- 首楼缓存只复用正文、作者和图片，标题、回复数、浏览数等列表信息仍以本次扫描为准；检测器版本变化时旧图片识别缓存会自动失效。
- 运行 `python scripts/evaluate_portrait_accuracy.py` 会复核最新一笔已完成的人像任务，并输出到 `data/portrait_eval/job_<任务编号>`；复核结果与页面数据来自完全相同的任务快照。
- 运行 `python scripts/reclassify_portrait_job.py --job-id <任务编号>` 可用当前模型重新识别已有任务快照，不会重新抓取贴吧列表。
- 贴吧接口可能限流或临时失败，工具内置了并发限制和短暂间隔。请控制抓取频率，并遵守网站条款及相关法律，仅采集你有权处理的公开内容。
